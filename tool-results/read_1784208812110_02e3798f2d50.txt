    22→    22→## Phase 1: The Editorial Eye (Content Transformation)
    23→    23→
    24→    24→Before you design, you must "edit the raw material". Users often provide dense, unstructured text. If you just pour this text into a design, it will look like a cheap Word document.
    25→    25→
    26→    26→You must apply **Editorial Pacing**:
    27→    27→
    28→    28→### 1. The Word Budget
    29→    29→No single page or visual canvas should exceed **150 words** of readable body text (the golden rule for maximum aesthetic impact). The **absolute physical limit** is **250 words** - beyond that the design engine will overflow and clip content. If the raw content exceeds 150 words:
    30→    30→- **Action A**: Brutally summarize it down to ≤150 words.
    31→    31→- **Action B**: Split it across multiple `pages` in your JSON blueprint.
    32→    32→- Only push to 150-250 words if the content genuinely cannot be cut further.
    33→    33→
    34→    34→### 2. Typographic Hierarchy Extraction
    35→    35→You must parse the raw text and categorize it into typographic roles:
    36→    36→- **Hero / Display**: The core emotional hook (1-5 words). Must be punchy.
    37→    37→- **Kicker / Eyebrow**: Tiny context text above a headline (e.g., "Q3 REPORT", "MANIFESTO").
    38→    38→- **Lead Paragraph**: The 2-3 sentence summary.
    39→    39→- **Data Sculptures**: Scan the text for impactful numbers (e.g., "97%", "$4.2M"). EXTRACT THEM. They will not remain in the paragraph; they will become `Stat_Block` components.
    40→    40→- **Pull Quotes**: Extract the most provocative sentence to stand alone as a visual anchor.

    44→    44→## Phase 2: The Component Lexicon
    45→    45→
    46→    46→You will construct your JSON Blueprint using ONLY the following components. These map directly to the `configs/components.md` assets. Do not invent new component types.
    47→    47→
    48→    48→> **⚠️ Markdown Content Limits**: For `Glass_Canvas`, the golden rule is **under 150 words** for maximum aesthetic breathing room. Absolute physical limit is **250 words**. If content exceeds 250 words, the design engine will overflow. You MUST summarize it or split it into a new page.
    49→    49→
    50→    50→### 1. `Hero_Typography`
    51→    51→Giant, page-dominating text. Usually interacts with the background via blend modes.
    52→    52→- **Parameters**:
    53→    53→  - `content` (string): The text (use `<br>` for deliberate line breaks).
    54→    54→  - `weight` (string): `"black"` (900, dominating) or `"thin"` (100, elegant).
    55→    55→  - `variant` (string, optional): `"standard"` only. ~~`"vertical_accent"`~~ is **NOT implemented** in `design_engine.py` - the engine silently ignores this value and renders nothing. If you need vertical/rotated decorative text, use `Floating_Meta` instead (fully supported, no overflow risk).
    56→    56→  - `scale` (integer, optional): Typographic scale level `1`-`6`. Controls font size via the engine's fluid type system. If omitted, the engine uses the default hero size.
    57→    57→    - `6`: Hero/Display - oversized title, clamp(64px, 12vw, 150px). Use for single words or short phrases with maximum visual impact.
    58→    58→    - `5`: Primary Title - clamp(48px, 8vw, 96px). Standard poster headline.
    59→    59→    - `4`: Subheadline - clamp(32px, 5vw, 56px). Chapter openers or key quotes.
    60→    60→    - `3`: Lead Paragraph - clamp(20px, 3vw, 32px). Prominent body text.
    61→    61→    - `2`: Body - 16px. Standard readable text.
    62→    62→    - `1`: Meta/Caption - 10px. Decorative, environmental.
    63→    63→
    64→    64→### 2. `Glass_Canvas`
    65→    65→The main structural container for reading text. Frosted glass, sharp 2px print corners.
    66→    66→- **Parameters**:
    67→    67→  - `markdown_content` (string): The actual text to read. Supports standard Markdown (H2, H3, bold, lists). *Must be under 150 words.*
    68→    68→  - `tension_score` (float, optional): Semantic tension value from `0.0` to `1.0`. Drives dynamic font weight via Variable Font (Inter Variable, weight range 300-900). The engine maps: `weight = 300 + (tension_score × 600)`.
    69→    69→    - `0.0-0.2` → Light (300-420): calm, contemplative passages
    70→    70→    - `0.3-0.5` → Normal (420-600): standard body text
    71→    71→    - `0.6-0.8` → Bold (600-780): urgent, assertive content
    72→    72→    - `0.9-1.0` → Max (780-900): crisis, climax, emotional peak
    73→    73→    - **When to use**: Multi-page narrative documents with emotional arc (case studies, pitch decks, manifestos). Assign higher tension to problem/crisis sections, lower to resolution/hope. Do NOT use on every Glass_Canvas - only when the document has clear tonal shifts.
    74→    74→    - **When NOT to use**: Data-heavy pages, simple reports, single-page posters.
    75→    75→
    76→    76→### 3. `Floating_Meta`
    77→    77→Tiny, environmental metadata (dates, edition numbers, catalog IDs) that lives in the 15% breathing margin.
    78→    78→- **Parameters**:
    79→    79→  - `position` (string): `"top-left"`, `"top-right"`, `"bottom-left"`, `"bottom-right"`.
    80→    80→  - `items` (array of strings): E.g., `["VOL 01", "2026", "EDITION 500"]`.
    81→    81→
    82→    82→### 4. `Hairline_Divider`
    83→    83→Structural 0.5px line. Not decorative; acts as a visual fold.
    84→    84→- **Parameters**:
    85→    85→  - `style` (string): `"bleed"` (goes edge-to-edge) or `"accent"` (short 30% width line).
    86→    86→
    87→    87→### 5. `Stat_Block`
    88→    88→Data sculpture. A massive number with a tiny label.
    89→    89→- **Parameters**:
    90→    90→  - `number` (string): e.g., `"97.3"`.
    91→    91→  - `unit` (string): e.g., `"%"`, `"Hz"`, `"$M"`.
    92→    92→  - `label` (string): e.g., `"COMPLETION RATE"`.
    93→    93→
    94→    94→### 6. `Image_Asset`
    95→    95→A visual element. The engine will apply a gradient blend to it.
    96→    96→- **Parameters**:
    97→    97→  - `source` (string): A URL, or a descriptive prompt if you expect the system to generate it.
    98→    98→  - `caption` (string, optional): Tiny text under the image.
    99→    99→
   100→   100→> ⚠️ **Image_Asset is for CONTENT images only** (user-provided photos, logos, diagrams, charts). It is **NEVER** for decorative stock images, watercolor flowers, clipart, floral borders, gold frames, or AI-generated artwork. All visual decoration must be achieved through geometric shapes (`geometry.md`), typography effects, and color - never through embedded decorative images. See `visual_framework.md` Stock Image Ban.
   101→   101→
   102→   102→### 7. `Page_Ghost_Number`
   103→   103→A giant, 4% opacity number acting as a watermark in the background.
   104→   104→- **Parameters**:
   105→   105→  - `number` (string): e.g., `"01"`, `"X"`.
   106→   106→
   107→   107→### 8. `Delta_Widget`
   108→   108→**Data-to-Ink Ratio enforcer.** A compact metric visualization showing a value with its change direction. CRITICAL: Use this instead of writing sentences like "revenue grew by 12%". Extract every trend into a Delta_Widget.
   109→   109→- **Parameters**:
   110→   110→  - `metric` (string): The metric name, e.g., `"REVENUE"`, `"LATENCY"`.
   111→   111→  - `value` (string): Current value, e.g., `"$4.2M"`, `"45ms"`.
   112→   112→  - `delta` (string): Change description, e.g., `"+12%"`, `"-45ms"`.
   113→   113→  - `trend` (string): `"up"`, `"down"`, or `"flat"`.
   114→   114→  - `label` (string, optional): Context line, e.g., `"vs. Q2 2025"`.
   115→   115→
   116→   116→### 9. `Process_List`
   117→   117→**Polymorphic adaptive component.** Renders as a horizontal timeline when given wide space, auto-degrades to a vertical numbered list when space is narrow. Use for workflows, steps, timelines.
   118→   118→- **Parameters**:
   119→   119→  - `steps` (array): Each item has `title` (string) and `description` (string).
   120→   120→
   121→   121→### 10. `Sidenote_Block`
   122→   122→**Tufte marginalia.** Used in `tufte_report` archetype layouts. Content is placed in the 30% side rail alongside the main column. Perfect for citations, supplementary data, asides, footnotes.
   123→   123→- **Parameters**:
   124→   124→  - `label` (string, optional): Category label, e.g., `"SOURCE"`, `"NOTE"`, `"DATA"`.
   125→   125→  - `body` (string): The sidenote content in Markdown.
   126→   126→
   127→   127→### 11. `Data-Aware Background` (via `data_points`)
   128→   128→Any component can carry an optional `data_points` array (e.g., `[10, 15, 8, 24, 30]`). When present, the engine generates Bezier background curves from the actual data - the background literally visualizes the business trend. Use on pages with financial, metric, or time-series content.

   132→   132→### ★ Advanced Components (Generative Micro-Typesetting)
   133→   133→
   134→   134→The following components are specialized generative design tools. They unlock visual effects that standard components cannot achieve. Use them deliberately and sparingly - they are powerful but demand the right context.
   135→   135→
   136→   136→### 8. `Shaped_Canvas`
   137→   137→A container where text flows around a non-rectangular shape. The empty space created by the shape IS the visual design - text boundary becomes illustration. Uses CSS `shape-outside` for non-rectangular text wrapping.
   138→   138→
   139→   139→- **Parameters**:
   140→   140→  - `shape_keyword` (string): One of `"circle"`, `"wave"`, `"diagonal_slash"`, `"diamond"`, `"wedge_right"`.
   141→   141→  - `markdown_content` (string): The text that will flow around the shape. Supports standard Markdown.
   142→   142→
   143→   143→- **Shape Selection Guide**:
   144→   144→  | shape_keyword | Visual Effect | Thematic Fit |
   145→   145→  |---------------|---------------|--------------|
   146→   146→  | `"circle"` | Text wraps around a circular void on the left | Unity, spotlight, focus |
   147→   147→  | `"wave"` | Wavy left text boundary | Ocean, flow, music, fluidity |
   148→   148→  | `"diagonal_slash"` | Diagonal cut across the page | Disruption, change, transformation |
   149→   149→  | `"diamond"` | Diamond-shaped negative space | Luxury, precision, crystalline |
   150→   150→  | `"wedge_right"` | Arrow/wedge pointing right | Direction, progress, forward motion |
   151→   151→
   152→   152→- **When to use**:
   153→   153→  - Artistic/editorial pages that need visual drama without images
   154→   154→  - Cover or section opener pages where you want a "wow" moment
   155→   155→  - When the content thematically maps to a recognizable shape
   156→   156→  - Only on pages with moderate text (100-200 words) - shape eats 30-40% of space
   157→   157→
   158→   158→- **When NOT to use**:
   159→   159→  - On data-heavy or dense content pages
   160→   160→  - Together with `Glass_Canvas` on the same page (visual conflict)
   161→   161→  - More than one `Shaped_Canvas` per page
   162→   162→
   163→   163→- **Archetype requirement**: Pages using `Shaped_Canvas` MUST use archetype `"shaped_editorial"` (relaxed safe-zone: 5% 6% inset).

   165→   165→### Chart & Data Visualization Styling
   166→   166→
   167→   167→**→ MUST READ: `typesetting/charts.md`** before designing any chart/data page.
   168→   168→
   169→   169→Key rules for Creative pipeline charts:
   170→   170→- **Donut > Pie**: Always use ring charts (hole ratio 60-70%), center area displays total/metric
   171→   171→- **Anti-stacking**: Small slices use leader lines or rich legends; bar labels auto-rotate to horizontal when text is long; line charts label only start/end/max/min
   172→   172→- **Axis cleanup**: Delete top/right spines, use dashed grid lines at 20% opacity (or delete grid entirely if values are labeled)
   173→   173→- **Bar micro-rounding**: 2-4px top border-radius, bar-to-gap ratio 1.5:1
   174→   174→- **Legend**: No border, horizontal top-left layout, small circle markers
   175→   175→- **Data-Ink Ratio**: Every element must represent data. If it doesn't, delete it.

   179→   179→## Phase 3: Page Archetypes (The Grid Strategy)
   180→   180→
   181→   181→For each page in your JSON, you must declare an `archetype`. This tells `design_engine.py` how to arrange the components you provided.
   182→   182→
   183→   183→- `"cover_hero"`: Cover page. **Must follow `typesetting/cover.md` 5-template system** - pick Layout 01/03/04/06/07 based on document tone. See "Cover Page Constitution" below for iron rules.
   184→   184→- `"split_vertical"`: Page split strictly 50/50 vertically. Left side image/svg, right side Glass_Canvas.
   185→   185→- `"editorial_flow"`: Top-down reading experience. Centered columns, generous margins. Use for main content.
   186→   186→- `"scattered_canvas"`: No grid. Elements placed via absolute positioning based on spatial weights.
   187→   187→- `"data_dashboard"`: 2x2 or 3x3 strict grid for multiple `Stat_Block`s.
   188→   188→- `"shaped_editorial"`: Relaxed safe-zone (5% 6% inset) designed for `Shaped_Canvas`. Centered, generous breathing room. **Must be used when the page contains a `Shaped_Canvas`.** Do NOT mix with `Glass_Canvas`.
   189→   189→- `"tufte_report"`: **Tufte marginalia layout.** 70% main content column + 30% sidenote rail. Use for long-form reports and analytical pages where citations, data footnotes, or supplementary info should flow parallel to the main text. Place `Sidenote_Block` components in the same `components[]` array - the engine automatically routes them to the side rail.
   190→   190→
   191→   191→### ★ 12×12 CSS Grid Coordinate System (Iron Rules)
   192→   192→
   193→   193→The layout engine uses a **12-track CSS Grid** for element placement. The grid lines are numbered **1 to 13** (12 tracks = 13 lines).
   194→   194→
   195→   195→**Absolute boundary rules - violation = broken layout:**
   196→   196→- **Column lines**: `1` = absolute left edge, `13` = absolute right edge. Full width = `1 / 13`.
   197→   197→- **Row lines**: `1` = absolute top edge, `13` = absolute bottom edge. Full height = `1 / 13`.
   198→   198→- **CRITICAL**: Never output a grid line number less than `1` or greater than `13`. Any value outside `[1, 13]` will destroy the layout.
   199→   199→
   200→   200→**`grid_area` format**: `"row_start / col_start / row_end / col_end"` (CSS shorthand).
   201→   201→- Example: `"1 / 1 / 7 / 13"` = top half of the page, full width.
   202→   202→- Example: `"3 / 8 / 6 / 13"` = rows 3-5, columns 8-12 (right side block).
   203→   203→
   204→   204→**40% whitespace rule**: At least 40% of grid cells (≥58 out of 144) must be left empty. Count your occupied cells.

   206→   206→### ★ Cover Page Constitution (5 Layout System)
   207→   207→
   208→   208→Cover pages (`archetype: "cover_hero"`) are the first impression. They must be ruthlessly sparse and spatially sophisticated.
   209→   209→
   210→   210→**→ MUST READ: `typesetting/cover.md`** before designing any cover.
   211→   211→
   212→   212→> **⚠️ Template Numbering:** Cover HTML templates use `cover.md`'s authoritative numbering: **01** (HUD), **03** (Academic Anchor), **04** (Academic Symmetric), **06** (Institutional), **07** (Crystal Blue). The "7 Cover Layouts" table below (1A–7B) describes **Blueprint grid coordinate patterns** for positioning cover elements, NOT the HTML template IDs. Do not confuse the two systems.
   213→   213→
   214→   214→#### Global Iron Rules (Always Apply)
   215→   215→
   216→   216→1. **Maximum 4 components** on any cover page. Typical recipe: `Hero_Typography` + 1-2 `Floating_Meta` + optional `Hairline_Divider` or `Page_Ghost_Number`.
   217→   217→2. **Typography Scale**: Title ≈ 45pt (2.5× base), Subtitle ≈ 25pt (1.4× base), Meta ≥ 18pt (never below 14pt). Covers with tiny text = FAIL.
   218→   218→3. **Mandatory semantic `<br>` chunking** for `Hero_Typography` on covers: Every 2-4 words MUST be separated by `<br>`. Single-line hero text is FORBIDDEN on covers. Example: `"ALGORITHMIC<br>FATIGUE"`, NOT `"ALGORITHMIC FATIGUE"`.
   219→   219→4. **Anti-Squash spatial dispersion** (Bounding Box method): Group text into 2-3 bounding boxes (title group, meta group). Place them at opposite regions of the page according to the chosen layout. Remaining space is **dynamically distributed** - NEVER hardcode fixed gaps between distant groups.
   220→   220→5. **No `Glass_Canvas` on cover pages.** Dense reading text kills the visual impact. Push all body content to page 2+.
   221→   221→6. **Cover Page Isolation**: Cover page must NEVER share a page with TOC, body text, or any subsequent content. The cover is always a standalone full page. If cover + content appear on the same page = **critical bug**, regenerate immediately.
   222→   222→7. **Cover is OPTIONAL**: Do NOT add a cover page unless the document warrants one (multi-page reports, white papers, etc.) or the user explicitly requests it. Short documents, letters, memos, forms, and quick outputs skip the cover.
   223→   223→8. **Background Layer (optional)**: See `typesetting/cover-backgrounds.md` for 3 recipes - A (极简弧线), B (工程十字轴+立柱), C (锐角切割+出血文字). Background renders BELOW all foreground at 2-5% opacity. Pick a recipe that matches the document tone. Never combine elements across recipes.

   256→   256→### ★ Component Grid Compatibility Constraints
   257→   257→
   258→   258→When placing advanced components into the 12×12 grid, obey these minimum size rules:
   259→   259→
   260→   260→- **`Glass_Canvas`**: Must occupy at least **6 columns × 4 rows** (e.g., `"3 / 1 / 7 / 7"`). Smaller areas will cause text overflow and padding collapse. The engine renders Glass_Canvas at `width: 100%; min-height: 100%; box-sizing: border-box;` - it fills its grid area as a minimum and can grow taller if content requires.
   261→   261→- **`Shaped_Canvas`**: Must occupy at least **8 columns × 6 rows** (e.g., `"2 / 3 / 8 / 11"`). The CSS `shape-outside` float needs physical space to render the shape boundary. Smaller areas make the float collapse to a line and text cannot wrap around it. **Must use archetype `"shaped_editorial"`.**
   262→   262→- **`Continuous Flow` background**: Renders in a separate `bg-layer` (`z-index: 1`, `position: absolute`), physically isolated from the grid system (`z-index: 2`). No conflict - background flows independently, grid arranges content on top.
   263→   263→
   264→   264→### ★ Content-Proportional Grid Row Allocation
   265→   265→
   266→   266→When **two or more text-heavy components** (e.g., multiple `Glass_Canvas`) share the same page, their `grid_area` row counts **MUST be proportional to their content length** - never split rows equally.
   267→   267→
   268→   268→**Estimation method:**
   269→   269→1. Count characters (or words) in each component's `markdown_content`
   270→   270→2. Allocate rows proportionally: `rows_i = total_rows × (chars_i / total_chars)`
   271→   271→3. Round to integers, minimum 3 rows per component
   272→   272→
   273→   273→**Example:**
   274→   274→```
   275→   275→Attractions content: 450 chars (3 items × 150 chars)
   276→   276→Food content: 250 chars (2 items × 125 chars)
   277→   277→Total available rows: 8 (rows 5→13)
   278→   278→
   279→   279→Attractions: 8 × 450/700 ≈ 5 rows → grid_area "5 / 1 / 10 / 13"
   280→   280→Food:        8 × 250/700 ≈ 3 rows → grid_area "10 / 1 / 13 / 13"
   281→   281→```
   282→   282→
   283→   283→**Why this matters:** Equal row allocation (4+4) causes the longer component to overflow into the shorter one's territory, creating text overlap in the final PDF. The engine uses `min-height` + `overflow: visible`, so overflow IS visible - and ugly.
   284→   284→
   285→   285→**Anti-pattern to avoid:**
   286→   286→```
   287→   287→❌ Two Glass_Canvas with very different text lengths both get "5/1/9/13" and "9/1/13/13"
   288→   288→✅ Longer one gets more rows: "5/1/10/13" and "10/1/13/13"
   289→   289→```

   373→   373→   - **`"auto"`: (RECOMMENDED DEFAULT). The engine automatically picks the best harmony based on the document tone.** Only override if you have a specific artistic reason.

   629→   629→## Pre-Flight Checklist (Self-Correction before generating output)
   630→   630→
   631→   631→Before you output the JSON block, verify:
   632→   632→0. ** VECTOR OUTPUT IRON RULE:** The final PDF MUST be generated via `page.pdf()` / `convert.blueprint` - NEVER `page.screenshot()` → image → wrap as PDF. Screenshot PDFs are blurry raster images. `page.pdf()` produces vector text that stays sharp at any zoom level.
   633→   633→1. **Did I write ANY HTML or CSS?** If yes, delete it. Only output JSON.
   634→   634→2. **Is any `Glass_Canvas` markdown content too long?** Count the words. Over 150? Summarize it or push to the next page.
   635→   635→3. **Is the JSON perfectly formatted?** Missing commas or unescaped quotes will crash the `design_engine.py` parser.
   636→   636→4. **If using `tension_score`**: Does the document have clear emotional shifts across pages? If all pages are the same tone, remove it.
   637→   637→5. **If using `continuous_flow`**: Is this multi-page (2+)? If single-page, switch to `"flow"`.
   638→   638→6. **If using `Shaped_Canvas`**: Is the archetype `"shaped_editorial"`? Is there at most one per page? No `Glass_Canvas` on the same page?
   639→   639→7. **Grid boundary check**: Are ALL `grid_area` values within `[1, 13]`? Any number < 1 or > 13 = FATAL ERROR.
   640→   640→8. **Component minimum size check**: `Glass_Canvas` ≥ 6col×4row? `Shaped_Canvas` ≥ 8col×6row?
   641→   641→9. **Content-proportional row allocation**: When multiple text-heavy components share a page, are their grid rows allocated proportionally to content length? Equal rows for unequal content = text overlap. (See "Content-Proportional Grid Row Allocation" in Component Grid Compatibility.)
   642→   642→9. **40% whitespace check**: Count occupied grid cells. At least 58 of 144 cells must be empty.
   643→   643→10. **Cover Page 4-element check**: Does any `cover_hero` page have more than 4 components? If yes, remove or merge components.
   644→   644→11. **Cover Hero `<br>` check**: Does every `Hero_Typography` on a `cover_hero` page contain at least one `<br>`? Single-line hero text on covers = FAIL.
   645→   645→12. **Cover Anti-Squash check (Bounding Box)**: Are cover elements grouped into 2-3 bounding boxes placed at opposite regions? Is remaining space dynamically distributed (not hardcoded gaps)? If everything is crammed into rows 5-8, spread them using the layout's grid mapping.
   646→   646→13a. **Cover Typography Scale check**: Is the hero title ≥ 45pt? Is subtitle ≥ 25pt? Is meta text ≥ 18pt (never below 14pt)? Tiny cover text = FAIL.

   676→   676→
   677→   677→When writing raw HTML/CSS for Playwright (bypassing the JSON Blueprint pipeline - e.g., resumes, menus, invitations, business cards, certificates, Japanese/Chinese vertical layouts):
   678→   678→
   679→   679→**⚠️ Iron rule: All bypass-scenario HTML→PDF conversions MUST use `html2pdf-next.js` — do NOT write custom Python Playwright scripts.** `html2pdf-next.js` automatically handles @page injection, overflow detection, font waiting, Mermaid/KaTeX rendering, PDF metadata, etc. See the "HTML→PDF Engine Selection Rules" section in SKILL.md.
   680→   680→
   681→   681→```bash
   682→   682→node "$PDF_SKILL_DIR/scripts/html2pdf-next.js" input.html --output output.pdf --width 210mm --height 297mm
   683→   683→```
   684→   684→
   685→   685→0. **Full-Bleed CSS (MANDATORY)**: Every HTML file for Playwright PDF MUST include:
   686→   686→   ```css
   687→   687→   @page { size: 800px 1200px; margin: 0; }  /* CONCRETE values only - CSS variables NOT supported in @page */
   688→   688→   html, body { margin: 0; padding: 0; width: 800px; }
   689→   689→   .page { width: 800px; height: 1200px; position: relative; }
   690→   690→   ```
   691→   691→   **⚠️ @page rules do NOT resolve CSS variables** (`var(--x)` is silently ignored, falls back to A4). Always use concrete `px` values.
   692→   692→   - Each `.page` div = one PDF page, with fixed `height` matching `@page` size.
   693→   693→   - **No `overflow: hidden`** on `.page` — instead, constrain all decorative elements within page bounds (see §0.75).
   694→   694→   - Content must fit within each `.page` — no cross-page flow.
   695→   695→   - `design_engine.py` handles this automatically via `override_css`.
   696→   696→
   697→   697→0.25. **Body Background for Multi-Page Mixed-Color Documents (MANDATORY)**:
   698→   698→   When an HTML document contains multiple `.page` divs with **different background colors** (e.g. dark cover + white body + dark specs page), Playwright's sub-pixel rounding creates <1px gaps at `.page` edges where `body` background shows through. On dark pages, a white `body` = visible white edges.
   699→   699→
   700→   700→   **Fix: set `html, body { background }` to the document's darkest page background color.**
   701→   701→
   702→   702→   ```css
   703→   703→   :root { --primary: #0f172a; }  /* darkest page color */
   704→   704→   html, body {
   705→   705→     margin: 0; padding: 0;
   706→   706→     width: 210mm;                 /* match @page size */
   707→   707→     background: var(--primary);   /* fills sub-pixel gaps with dark color */
   708→   708→   }
   709→   709→   ```
   710→   710→
   711→   711→   **Why this doesn't break white pages:** White `.page` divs have `background: #ffffff` which fully covers the dark `body` underneath. The dark body only shows through the <1px sub-pixel gap at the extreme page edge - imperceptible on white pages after anti-aliasing.
   712→   712→
   713→   713→   **Selection rule:**
   714→   714→   - All pages same color → `body { background: <that color> }`
   715→   715→   - Mixed dark + light pages → `body { background: <darkest page color> }` (dark edges on white pages are invisible; white edges on dark pages are the bug we're fixing)
   716→   716→   - All pages white/light → `body { background: <lightest content bg> }` (e.g. `#f8fafc`)
   717→   717→
   718→   718→0.5. **No overflow:hidden anywhere + Browser Preview Adaptive Scaling (MANDATORY)**:
   719→   719→   **Never** set `overflow: hidden` on `html`, `body`, `.page`, or any container. Reasons:
   720→   720→   - It silently clips content that slightly exceeds bounds, making layout bugs invisible.
   721→   721→   - `html2pdf-next.js`'s pre-render check detects `scrollHeight > clientHeight` + `overflow: hidden` and triggers auto-fix (force-expanding the container), which may break the layout.
   722→   722→   - Instead, constrain decorative elements within page bounds at the CSS level (see §0.75).
   723→   723→
   724→   724→   **`design_engine.py` handles this automatically**: During blueprint compilation, it auto-injects `@media screen` centering + scaling code, and the `html` background color uses `var(--c-bg)` matching the poster's main color. No manual addition needed.
   725→   725→
   726→   726→   **Correct approach when writing HTML manually**: Remove `overflow: hidden` and manually add `@media screen` scaling preview:
   727→   727→   ```css
   728→   728→   /* Fixed canvas size, no overflow */
   729→   729→   html, body { margin: 0; padding: 0; width: 800px; height: 1400px; }
   730→   730→   .page { width: 800px; height: 1400px; position: relative; }
   731→   731→
   732→   732→   /* Auto-scale to viewport in browser preview for full-page view */
   733→   733→   @media screen {
   734→   734→     html {
   735→   735→       height: auto;
   736→   736→       display: flex;
   737→   737→       justify-content: center;
   738→   738→       background: #0a0a1a; /* Surround color — must match poster's main background */
   739→   739→     }
   740→   740→     body {
   741→   741→       transform-origin: top center;
   742→   742→       scale: min(1, calc(100vw / 800), calc(100vh / 1400)); /* Consider both width and height */
   743→   743→       margin: 0 auto;
   744→   744→       box-shadow: 0 0 60px rgba(0,0,0,0.3); /* Optional: shadow to distinguish canvas in preview */
   745→   745→     }
   746→   746→   }
   747→   747→   ```
   748→   748→   `@media screen` rules only apply in browser preview; `page.pdf()` uses print media and is unaffected.
   749→   749→   **Every fixed-size HTML must include this `@media screen` adaptive code.**
   750→   750→
   751→   751→0.75. **Decorative Element Containment (MANDATORY — replaces overflow:hidden)**:
   752→   752→   **Do NOT use `overflow: hidden` on `.page` containers.** It silently clips content that slightly exceeds bounds, making layout errors invisible and debugging painful.
   753→   753→
   754→   754→   Instead, **constrain all decorative elements within page bounds at the CSS level**:
   755→   755→
   756→   756→   ```css
   757→   757→   /* ✅ CORRECT: decorative element stays inside .page */
   758→   758→   .deco-circle {
   759→   759→       position: absolute;
   760→   760→       width: 80%;           /* NOT >100% */
   761→   761→       height: 40%;
   762→   762→       top: 10%;
   763→   763→       right: 0;             /* NOT negative */
   764→   764→       border-radius: 50%;
   765→   765→       opacity: 0.1;
   766→   766→   }
   767→   767→
   768→   768→   /* ❌ FORBIDDEN: causes scrollWidth > pageWidth → Playwright shrinks everything */
   769→   769→   .deco-circle-bad {
   770→   770→       position: absolute;
   771→   771→       width: 200%;          /* inflates scrollWidth */
   772→   772→       left: -50%;           /* extends beyond left edge */
   773→   773→   }
   774→   774→   ```
   775→   775→
   776→   776→   **Iron rules for decorative elements:**
   777→   777→   - `width` ≤ 100% of `.page` width. No exceptions.
   778→   778→   - `left` ≥ 0, `right` ≥ 0. No negative offsets that push content beyond page edges.
   779→   779→   - For edge-bleeding effects, position the element at the edge and let `border-radius` or `opacity` create the visual bleed within bounds.
   780→   780→   - For horizontal flex layouts (≥3 items), always add `flex-wrap: wrap` to prevent horizontal overflow.
   781→   781→
   782→   782→   **Why not overflow:hidden?**
   783→   783→   Playwright’s `page.pdf()` checks `body.scrollWidth`. If any absolutely-positioned child pushes `scrollWidth` beyond `@page` width, Playwright shrinks **all content** to fit. `overflow:hidden` masks this by clipping, but also silently hides any content that slightly exceeds bounds. Constraining elements at the source eliminates both the shrink bug and the silent clipping.
   784→   784→
   785→   785→   See `typesetting/overflow.md` §3.5 for additional horizontal overflow rules.
   786→   786→
   787→   787→1. **Character Encoding Safety**: Never use Japanese kana (の, が, は), rare symbols, or Private Use Area characters in content strings. They corrupt to U+FFFD (�) during LLM→file write→read transit. Replace with plain Chinese equivalents: `の`→`之/的/缔/省略`.
   788→   788→2. **Vertical Chinese Text** - When using `writing-mode: vertical-rl` for CJK, you MUST include:
   789→   789→   ```css
   790→   790→   writing-mode: vertical-rl;
   791→   791→   text-orientation: upright;    /* Each glyph stands upright */
   792→   792→   white-space: nowrap;          /* Prevent word-wrap breaking single chars to new column */
   793→   793→   letter-spacing: 12px;         /* Typical CJK vertical spacing */
   794→   794→   ```
   795→   795→   Without `text-orientation: upright`, Latin/fallback fonts render rotated 90°. Without `white-space: nowrap`, CJK characters may wrap into unexpected multi-column layouts (e.g., 3 chars on one line + 1 char alone on next).
   796→   796→3. **Font Coverage**: For CJK content via Playwright, always load Google Fonts Noto Serif SC or Noto Sans SC via `<link>` tag in `<head>` (NOT `@import` in CSS - `@import` must be the very first rule in a stylesheet or it's silently ignored). Example:
   797→   797→   ```html
   798→   798→   <link href="https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@300;400;500;700;900&display=swap" rel="stylesheet">
   799→   799→   ```
   800→   800→   System CJK fonts vary across macOS/Linux - Google Fonts guarantee glyph coverage without relying on system fonts. `design_engine.py` already handles this automatically via `<link>` tag.
   801→   801→4. **Post-Generation Text Verification**: After Playwright renders the PDF, extract text from every page and scan for `?` or `\ufffd`. If found, the source HTML has encoding-corrupted characters that must be replaced in the Python source.
   802→   802→5. ** HTML Pre-Render Validation (MANDATORY)**: After writing the HTML file and before running `html2pdf-next.js`, always run the HTML validator:
   803→   803→   ```bash
   804→   804→   python3 "$PDF_SKILL_DIR/scripts/poster_validate.py" check-html <your_file>.html
   805→   805→   ```
   806→   806→   - **ERROR** items (e.g. `OVERFLOW_HIDDEN_CONTAINER`, `FONT_NO_FALLBACK`) → must fix before PDF generation. Use `--fix --output <file>.html` for auto-repair.
   807→   807→   - **WARNING** items (e.g. `FIXED_SIZE_NO_SCREEN_ADAPT`, `SCREEN_ADAPT_NO_SCALE`, `COLOR_CONTRAST`) → review and fix where appropriate.
   808→   808→   - This catches the most common bypass HTML bugs: `overflow:hidden` on containers, missing `@media screen` auto-scale for fixed-size pages, font-family without generic fallback, low contrast text, etc.

   816→   816→### Color (palette.md)
   817→   817→
   818→   818→- [ ] **Entire document ≤ 5 colors**: Primary + secondary + accent + neutral + background
   819→   819→- [ ] **All colors traceable to primary**: Secondary and accent derived via lightness/saturation/micro-hue shift

   822→   822→- [ ] **No high-saturation color blocks**: Avoid eye strain

   825→   825→
   826→   826→- [ ] **Anchors use only the primary color**: Layer via opacity, don't mix colors
   827→   827→- [ ] **Strokes over fills**: Solid elements ≤ 30%
   828→   828→- [ ] **Ultra-thin lines**: stroke-width 0.3-0.8px
   829→   829→- [ ] **Asymmetric placement**: Offset creates tension
   830→   830→- [ ] **Elements ≤ 8**: Restraint, don't clutter

   832→   832→### Global Layout
   833→   833→
   834→   834→- [ ] **Full-bleed enforcement**: `@page { size: <w> <h>; margin: 0; }` and `html,body { margin:0; padding:0; }`
   835→   835→- [ ] **Background color consistency**: `html, body { background }` set explicitly. Single-color docs: match content canvas. Multi-page mixed docs: use darkest page's background
   836→   836→- [ ] **Content centering**: Symmetric inset/padding, no left/right drift
   837→   837→- [ ] **Anti-void edges**: Content fills ≥ 60% (multi-page) or ≥ 70% (single-page poster/infographic)

   841→   841→
   842→   842→- [ ] **Decorative elements ≤ 3 per page**: Cover page exempt
   843→   843→- [ ] **No rainbow/multi-color schemes**: Stick to single-family palette
   844→   844→- [ ] **No texture/pattern backgrounds**: Solid or ultra-light tinted only
   845→   845→- [ ] **Whitespace is design**: Don't fill every gap with decorative elements
   846→   846→- [ ] **Typography over decoration**: Create hierarchy through font size/weight/spacing/color
   847→   847→- [ ] **2-typeface maximum**: At most 2 font families
   848→   848→- [ ] **🚫 NO stock images / clipart / AI-generated decorations**: Only user-provided content images allowed
